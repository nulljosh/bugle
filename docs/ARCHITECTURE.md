# Architecture

Bugle is one reader in two languages. The apps (iPhone, iPad, Mac, Watch, plus a widget) share one Swift core; the web reader mirrors each rule in plain JavaScript, and `test.mjs` pins the shared cases so the two cannot drift. `architecture.svg` draws the same picture.

## How it runs

A refresh fetches every followed feed at once, parses each into entries tagged with their outlet, drops muted outlets and words, groups the same story across newsrooms (`Coverage.cluster`) and ranks Today (`Coverage.today`). The app caches the result to disk and refreshes in the background; the web reader fetches through `/feed`, a Cloudflare Pages function, because publishers send no CORS headers.

## Gotchas

- The Xcode project is `journal.xcodeproj` and the iOS scheme `Journal-iOS`; the bundle id `com.nulljosh.journal` is locked from before the renames.
- Deploy the web from the bugle root (`npx wrangler pages deploy --branch=main`), never from `web/`, or `functions/` is left out. Bump the `?v=` on reader assets and `CACHE` in `sw.js` on every web change.
- The pre-commit hook rejects files over about 5000 tokens; split a file before it grows past that.
- DEBUG self-checks run at launch in `JournalApp.init`; `node test.mjs` covers the web side.
